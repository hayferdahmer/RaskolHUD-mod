# RaskolHUD — дорожная карта до 1.0.0

## Цель

Выпустить законченный клиентский HUD для Minecraft 26.2 / Fabric и Paper-мост для RASKOL. Сервер остаётся единственным источником игровых данных. Клиент отвечает за визуализацию, персонализацию и локальные настройки.

Работа ведётся в ветке `feat/0.6.0-hud-customization` и PR #5. До отдельного решения владельца проекта изменения не переносятся в `main`; теги и GitHub Releases до приёмки 1.0.0 не создаются.

## Зафиксированные архитектурные правила

- `RaskolClasses` — источник истины для класса, специализации, уровня, ресурсов, эффектов, DoT, CC, талантов и боевых характеристик.
- `RaskolHUD-mod` — единственное место для клиентского HUD, общего протокола и Paper-моста. HUD-код не переносится в RaskolClasses.
- Paper HUD остаётся полноценным fallback. Fabric-мод необязателен и добавляет расширенную визуализацию только игроку с установленным клиентом.
- Клиент не рассчитывает боевые значения, не предсказывает кулдауны и не подменяет неизвестные серверные данные.
- Если источник данных недоступен, поле не показывается как достоверное значение. Никаких выдуманных максимумов, XP или уровней.
- Локальные настройки не отправляются на сервер.
- Совместимость проверяется на Java 25, Minecraft/Paper 26.2, Fabric Loader 0.19.5, Fabric API 0.161.0+26.2 и Gradle 9.5.1.

## Этапы

### 0.6.0 — персонализация HUD (текущая ветка)

- Независимые переключатели блоков и декоративных элементов.
- Масштабирование, перемещение, прозрачность и сброс.
- Локальное сохранение настроек.
- Возврат ванильных элементов, если соответствующая секция HUD отключена.
- Проверка сохранения настроек и поведения при потере соединения.

**Состояние:** код и документация находятся в PR #5; CI Run #87 успешен. Ручная проверка в Minecraft ещё не выполнена.

### 0.7.0 — расширенная карточка персонажа

- Отдельный компактный блок боевых характеристик.
- Отображение только значений, реально опубликованных RaskolClasses: физическое/магическое сопротивление, уклонение, парирование, шанс критического удара ближнего боя и заклинаний.
- Отображение доступных очков талантов и прогресса распределения талантов, если данные корректно присутствуют в серверном снимке.
- Независимое включение/выключение блока, его масштабирование, позиционирование и прозрачность.
- Проверки корректного поведения при пустых, отсутствующих и некорректных данных.

### 0.8.0 — рамка цели и боевой контекст

**Реализовано в текущей ветке; ожидает CI-проверки и последующей ручной приёмки.**

- Компактная рамка текущей цели: имя, тип существа и здоровье.
- Уровень цели показывается только если его возвращает зарегистрированный `EntityLevelProvider`; иначе строка уровня скрыта.
- Для игроков показываются только доступные серверные сведения; клиент не пытается определять класс, фракцию или боевой статус самостоятельно.
- Обновление цели без мерцания, очистка при потере цели, смерти, выходе из радиуса или смене мира.
- Сервер отправляет данные цели только прошедшим handshake клиентам RaskolHUD.

### 0.9.0 — доведение UX и совместимости

- Редактор расположения HUD с понятной обратной связью и безопасными границами экрана.
- Привязки блоков к краям/центру экрана, чтобы настройки не ломались при смене разрешения и GUI Scale.
- Завершение русской и английской локализации.
- Проверка миграции старых конфигов и восстановление настроек при повреждённом файле.
- Ограничение частоты и размера сетевых обновлений, очистка состояния при disconnect/reconnect и устаревших пакетах.
- Проверка fallback без Fabric-мода и при временной недоступности серверного моста.

### 1.0.0 — стабилизация и выпуск

- Полный автоматический набор тестов протокола, валидации данных и конфигурации.
- Интеграционная проверка Paper-моста с актуальным RaskolClasses и PlaceholderAPI.
- Проверка производительности: никаких тяжёлых reflection/API-вызовов в render loop и лишних выделений на каждом кадре.
- Проверка UI на нескольких разрешениях и значениях GUI Scale.
- Полная документация установки, совместимости, настроек и устранения неполадок.
- Финальный аудит безопасности сетевых пакетов и поведения при недоверенных/устаревших данных.
- Ручная приёмка владельцем проекта на реальном сервере.
- Только после отдельного подтверждения: снять Draft, подготовить релиз 1.0.0 и решить вопрос о переносе в `main`.

## Явно не включено без появления серверного контракта

- Полоса XP/опыта персонажа: текущий CharacterLevelService возвращает вычисленный уровень, но не предоставляет универсальные текущие/следующие пороги прогресса. Проценты прогресса нельзя выводить из уровня.
- Клиентский расчёт урона, исцеления, брони, сопротивлений, ресурсов, талантов или кулдаунов.
- Любые изменения баланса и правил RaskolClasses.
- Обязательная установка Fabric-мода для игры на сервере.

## Критерии готовности 1.0.0

1. Все заявленные блоки используют только подтверждённые серверные данные.
2. Ванильный HUD и Paper fallback не ломаются, если мод отсутствует, отключён или теряет соединение.
3. Пользователь может настроить видимость, положение, масштаб и прозрачность предусмотренных блоков; настройки переживают перезапуск.
4. Цель корректно появляется и исчезает во всех предусмотренных сценариях.
5. Протокол отвергает несовместимые, повреждённые, чрезмерно большие и устаревшие пакеты.
6. CI зелёный; тесты и документация соответствуют фактическому поведению.
7. Ручная приёмка выполнена владельцем проекта.
8. До отдельного разрешения владельца `main` остаётся без изменений.
