# RaskolHUD

Клиентский HUD-мод для сервера «РАСКОЛ | ДВЕ КОРОНЫ».

## Границы репозиториев

- Этот репозиторий (RaskolHUD-mod) — единственное место разработки клиентского мода, общего протокола и Paper-моста.
- [RaskolClasses](https://github.com/hayferdahmer/RaskolClasses) — upstream-источник истины для классов, специализаций, уровня персонажа, здоровья и классового ресурса. Здесь читаются актуальные контракты и правила. Код HUD сюда не переносится.

## Платформа

- Minecraft 26.2
- Java 25
- Fabric Loader 0.19.5
- Fabric API 0.161.0+26.2
- Paper 26.2 для серверного моста
- Fabric Loom 1.17.21
- Gradle 9.5.1

## Структура

- `protocol/` — общий бинарный протокол, DTO серверного состояния и тесты.
- `client/` — клиентский Fabric-мод, который рисует HUD через Fabric HUD API.
- `bridge/` — Paper-плагин, который читает значения PlaceholderAPI игрока и отправляет снимок только клиентам RaskolHUD.

## Первая версия HUD

В игровом интерфейсе показываются:
- класс, специализация и уровень персонажа;
- здоровье и классовый ресурс в нижней панели по сторонам от хотбара;
- броня и сытость в том же стиле;
- активные эффекты класса и периодический урон (DoT) с серверными таймерами и стаками;
- серверный scoreboard, перерисованный клиентом в оформлении РАСКОЛа;
- наличие свежей связи с серверным мостом.

Клиент не пересчитывает характеристики, класс, прогрессию, боевые эффекты или ресурсы. Сервер остаётся единственным источником истины. Если снимок не пришёл или устарел более чем на 5 секунд, HUD скрывается.

При наличии актуального снимка HUD заменяет стандартные полосы здоровья, брони и голода единым нижним интерфейсом: здоровье и классовый ресурс расположены по сторонам от хотбара, броня и сытость показаны в том же визуальном стиле. Класс, специализация и уровень остаются в верхней панели. Боковой scoreboard рендерится заново на клиенте из синхронизированных scoreboard-данных Minecraft; его строки и значения остаются серверными, меняется только оформление. Под верхней панелью отображаются активные эффекты и DoT, полученные из RaskolClasses. Ванильный боковой scoreboard и ActionBar локально скрываются, чтобы не дублировать данные. Если снимок отсутствует или устарел, ванильные полосы и скрытые элементы автоматически возвращаются. Хотбар, прицел, опыт, титры и остальные стандартные элементы сохраняются. Эти изменения затрагивают только экран игрока с установленным RaskolHUD и не меняют отображение у остальных подключённых игроков.

## Установка для тестирования

Клиентская и серверная части устанавливаются **в разные места**. Клиентский мод не нужно копировать на Paper-сервер.

### На компьютере игрока

1. Установи Minecraft 26.2 с Fabric Loader 0.19.5.
2. Установи Fabric API версии 0.161.0+26.2 для этой же версии Minecraft.
3. Скопируй `raskolhud-client-0.1.0.jar` в папку `mods` используемого профиля Minecraft.
   - В стандартном лаунчере Windows это обычно `%APPDATA%\\.minecraft\\mods`.
   - В стороннем лаунчере используй папку `mods` конкретного экземпляра/профиля.
4. Запусти игру через Fabric-профиль.

### На Paper-сервере

1. Убедись, что сервер работает на Paper 26.2 и Java 25.
2. Установи на сервер актуальные плагины RaskolClasses и PlaceholderAPI.
3. Скопируй `raskolhud-bridge-0.1.0.jar` в папку `plugins` Paper-сервера.
4. Перезапусти сервер.

После этого подключись к серверу с Fabric-клиента. Клиент отправит handshake, мост начнёт отправлять данные игрока, а HUD появится после получения первого корректного снимка.

**Не перепутай файлы:**
- `raskolhud-client-0.1.0.jar` → клиент Minecraft, папка `mods`.
- `raskolhud-bridge-0.1.0.jar` → Paper-сервер, папка `plugins`.

## Что проверить в первом запуске

- Появляются ли класс, специализация и уровень персонажа.
- Совпадают ли здоровье и ресурс с серверными данными.
- Отображаются ли броня и сытость в нижней панели и меняются ли вслед за состоянием игрока.
- Не перекрывают ли боковые панели хотбар и полосу опыта при разных GUI scale и разрешениях.
- Появляется ли индикатор активной связи после подключения.
- Исчезает ли HUD после отключения от сервера или потери актуальных снимков.
- Не перекрывает ли HUD элементы интерфейса на твоём разрешении и масштабе GUI.

## Совместимость с текущим RaskolClasses

Мост первой версии использует существующие плейсхолдеры:
- `%raskolclasses_class%`
- `%raskolclasses_level%`
- `%raskolclasses_hp%`
- `%raskolclasses_hp_max%`
- `%raskolclasses_resource%`
- `%raskolclasses_spec%`

Названия ресурсов и символы берутся из проверенной текущей модели классов RaskolClasses. Пока публичный снимок не предоставляет фактический максимум классового ресурса, мост отправляет его как неизвестный. Поэтому клиент показывает текущее значение без выдуманной шкалы. Для полноценной шкалы понадобится отдельное согласованное расширение публичного PlaceholderAPI/API-контракта в RaskolClasses; оно не включается в этот репозиторий и не меняет исходный плагин автоматически.

## Протокол связи

- Клиент отправляет однобайтовый handshake версии протокола по `raskolhud:hello`.
- Мост отвечает серверным снимком по `raskolhud:state`.
- Снимки отправляются раз в 10 серверных тиков только игрокам, прошедшим handshake.
- Пакет содержит сигнатуру, версию, timestamp, ограниченные UTF-8 строки и числовые поля.
- Клиент проверяет структуру и версию пакета и удаляет состояние при отключении.

## Сборка

Из корня репозитория при наличии JDK 25:

```bash
gradle :protocol:test :client:build :bridge:build
```

Артефакты:
- `client/build/libs/raskolhud-client-0.1.0.jar`
- `bridge/build/libs/raskolhud-bridge-0.1.0.jar`

## Статус

Версия 0.1.0 собрана CI на Java 25 / Gradle 9.5.1; protocol unit tests проходят. Это первый тестовый билд, а не подтверждённый production-релиз: реальный запуск на клиенте Minecraft 26.2 и проверка handshake на Paper 26.2 ещё должны быть выполнены. До этого не следует считать совместимость в игровом процессе окончательно подтверждённой.
