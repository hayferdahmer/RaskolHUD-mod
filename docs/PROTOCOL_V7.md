# RaskolHUD wire protocol v7

## Каналы

- `raskolhud:hello` — клиент → сервер, однобайтовый номер версии протокола.
- `raskolhud:state` — сервер → клиент, бинарный снимок состояния HUD.
- `raskolhud:signal` — сервер → клиент, краткоживущий классовый сигнал прицела.

Сервер отправляет состояние только игрокам, прошедшим handshake с текущей версией протокола.

## Порядок полей пакета состояния

1. Magic `0x52534844`.
2. Protocol version `7`.
3. Unix timestamp снимка в миллисекундах.
4. Строки: class ID, имя класса, специализация, имя ресурса, символ ресурса, фракция, титул.
5. Целые значения: уровень персонажа, здоровье/максимум, ресурс/максимум.
6. Три ограниченных списка эффектов: активные эффекты, DoT, CC.
7. Ограниченный список кулдаунов с исходным слотом хотбара.
8. Дополнительные боевые характеристики и данные талантов.
9. Текущая цель или маркер отсутствующей цели.

Все строки кодируются UTF-8 и ограничены 128 байтами. Размер всего пакета ограничен 4096 байтами.

## Данные и доверие

- Все игровые значения готовит Paper-мост из RaskolClasses, PlaceholderAPI и Bukkit/Paper API.
- Клиент только отображает снимок; он не рассчитывает урон, ресурсы, кулдауны, характеристики или прогрессию.
- Уровень моба передаётся только при наличии EntityLevelProvider.
- Уровень персонажа ограничен 1–60. Неизвестные данные не подменяются вымышленными значениями.
- Цель выбирается сервером по направлению взгляда игрока в пределах 32 блоков.
- Клиент отвергает неправильную сигнатуру, неизвестную версию, некорректные размеры, обрезанные данные, некорректный UTF-8, лишние байты и недопустимые значения.
- Запоздавший снимок с timestamp не новее последнего принятого игнорируется.
- При disconnect клиент очищает текущее состояние.

## Версионирование

Любое несовместимое изменение структуры требует увеличения `PROTOCOL_VERSION` и синхронного обновления клиента и Paper-моста. Старые клиенты не получают новый пакет состояния, а новый клиент не принимает пакет предыдущей версии.
